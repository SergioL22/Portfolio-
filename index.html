BioLyra

Agentic biomedical AI assistant

An agent built to answer biomedical questions the way a researcher would: pull from what's already known, and go looking when the question calls for something recent. A LangGraph router sends each query down one of three paths — casual conversation, retrieval over a ChromaDB index of ~2,500 PubMed abstract chunks embedded with BioBERT, or a live NCBI Entrez search when the question flags something recent (a year like "2025" in the query is enough to trigger it). The answer is then synthesized by a Phi-3.5-mini model QLoRA fine-tuned on PubMedQA (4-bit NF4 quantization, LoRA rank 16). He evaluated the fine-tune against the base model with BERTScore, tracked runs in Weights & Biases, and shipped it two ways: a Gradio chat interface and a FastAPI REST endpoint.

Grew out of an earlier project, Lyra — his first local AI assistant, running on Ollama and Llama 3.1 with Flask and SQLite — which he rebuilt with more advanced RAG techniques and renamed.

02

Forge

From-scratch LLM training (JAX) + high-performance Rust inference

A decoder-only transformer (13.69M parameters), hand-written from scratch in JAX — no HuggingFace AutoModel, hand-rolled attention, RoPE, and RMSNorm — and trained on TinyStories. Inference is then reimplemented independently in Rust and numerically verified against the JAX model before any performance claim is trusted, then incrementally optimized: KV caching, static and continuous batching, and INT8 quantization, each step benchmarked against the last.

Python baseline
13.7 tok/s
Rust engine
105.2 tok/s

Every number is measured, not estimated: the Rust engine runs 7.7x faster than the Python baseline (105.2 vs 13.7 tok/s), KV caching alone is a 5.2x speedup, and INT8 quantization cuts memory 58% for +0.01% perplexity — and where an optimization didn't pay off on this hardware, that's reported too, not hidden.

Trained for 20,000 steps on 912,112 packed TinyStories sequences; the original batch size of 64 OOM'd on the 12GB training GPU, fixed with batch size 16 and 4-step gradient accumulation to preserve the intended effective batch size.

Research Desk

Stock & ETF research built on public SEC data

A FastAPI web app for researching US stocks and ETFs. Free market-data APIs don't allow their prices to be shown publicly, so the app is built on public SEC EDGAR filings instead: ten years of reported fundamentals, any US ticker on demand, insider-trading summaries from Form 4s, ETF holdings and overlap from Form N-PORT, and filing alerts for a watchlist. Price tools such as indicators, risk measures and a hypothetical investment simulator run in the browser on a CSV the visitor opens, so no prices are ever redistributed.

Covered by about 600 offline tests. A monthly GitHub Action rebuilds the data snapshot, and the server caches and rate-limits every SEC request.
